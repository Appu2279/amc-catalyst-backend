Section 1 — Introduction

Base URL, authentication, and response conventions

Base URL

https://your-domain.com/api

Authentication

Most endpoints require a JWT token in the Authorization header. Obtain the token from the login endpoint.

Authorization: Bearer <your_jwt_token>
Two roles exist: user (student) and admin. Admin endpoints return 403 if a regular user token is used.

Standard Response Format

Success
// Single object
{ "id": 1, "title": "...", ... }

// Paginated list
{
  "data": [ ... ],
  "pagination": {
    "total": 240,
    "page": 1,
    "limit": 20,
    "pages": 12
  }
}
Error
{ "message": "Unauthorized" }
{ "error": "column ... does not exist" }

Auth Badge Legend

BadgeMeaning
PUBLICNo token required
USERAny valid JWT token
ADMINJWT token with role = admin

Section 2 — Authentication

Register, login, and get your JWT token

POST /auth/register PUBLIC

Create a new student account. Role defaults to user.

Request Body

FieldTypeRequiredDescription
namestringYesFull name
emailstringYesMust be unique
passwordstringYesMin 6 characters recommended
Example Request
POST /api/auth/register
{
  "name": "Appu",
  "email": "appu@example.com",
  "password": "secret123"
}
Response 201
{ "token": "eyJhbGci...", "user": { "id": 1, "name": "Appu", "role": "user" } }
POST /auth/login PUBLIC

Authenticate and receive a JWT token. Save this token — it goes in every subsequent request header.

Request Body

FieldTypeRequired
emailstringYes
passwordstringYes
Response 200
{ "token": "eyJhbGci...", "user": { "id": 1, "name": "Appu", "role": "admin" } }
Store the token in localStorage or a cookie on the frontend and attach it to every request.

Section 3 — Subjects & Topics

Organize questions by medical subject and topic

Subjects are top-level categories (e.g., Anatomy, Physiology). Topics are subcategories within a subject (e.g., ECG under Cardiology). Questions are always assigned to a subject and optionally to a topic.
GET /subjects PUBLIC

List all active subjects with their topics. Use this to populate subject filter dropdowns on the frontend.

Response
[
  {
    "id": 1, "name": "Anatomy", "slug": "anatomy",
    "topics": [
      { "id": 3, "name": "Upper Limb", "slug": "upper-limb" }
    ]
  }
]
GET /subjects/:id/topics PUBLIC

Get all topics for a specific subject. Use when a student selects a subject and you need to populate the topic dropdown.

POST /subjects ADMIN

Create a new subject. Slug is auto-generated from the name.

FieldTypeRequired
namestringYes
descriptionstringNo
POST /subjects/topics/create ADMIN

Create a new topic under a subject.

FieldTypeRequired
subject_idintegerYes
namestringYes
descriptionstringNo
PUT /subjects/:id ADMIN

Update a subject. Pass is_active: false to hide it from students without deleting.

PUT /subjects/topics/:id ADMIN

Update a topic name, description, or active status.

DELETE /subjects/:id ADMIN

Permanently delete a subject. Prefer is_active: false instead — deletion may break existing questions that reference this subject.

This is a hard delete. Set is_active: false to soft-disable instead.

Section 4 — Questions

Admin CRUD and student QBank browsing (paginated)

Security rule: Student-facing endpoints never return is_correct on options. Only the Admin endpoints and the result endpoint (after test submission) reveal correct answers.

Student Endpoints

GET /questions PUBLIC

Browse the question bank with filters and pagination. Returns questions without revealing correct answers. Use this for the QBank practice section.

Query Parameters

ParamTypeExampleDescription
subject_idinteger1Filter by subject
topic_idinteger3Filter by topic
difficultystringhardeasy / medium / hard
question_typestringsingle_choicesingle_choice / multiple_choice / true_false / image_based
source_typestringprevious_yearqbank / recall / mock / previous_year
searchstringECGFull-text search in question text
pageinteger1Page number (default: 1)
limitinteger20Items per page (max: 100, default: 20)
Example
GET /api/questions?subject_id=1&difficulty=hard&page=2&limit=10
Response
{
  "data": [
    {
      "id": 42,
      "question_text": "A 45-year-old presents with chest pain...",
      "difficulty": "hard",
      "subject": { "id": 1, "name": "Cardiology" },
      "QuestionOptions": [
        { "id": 1, "option_key": "A", "option_text": "Myocardial Infarction" }
        // no is_correct field
      ]
    }
  ],
  "pagination": { "total": 86, "page": 2, "limit": 10, "pages": 9 }
}
GET /questions/:id PUBLIC

Get a single question by ID with all its options (no correct answer flag). Use when a student clicks on a specific question in QBank practice mode.

Admin Endpoints

GET /questions/admin ADMIN

List all questions (active and inactive) with correct answers visible. Supports all the same filter params as the student endpoint plus is_active.

POST /questions/admin ADMIN

Manually create a question with its options in one request. Use this for adding individual questions without the import pipeline.

FieldTypeRequiredNotes
subject_idintegerYesMust exist in subjects table
topic_idintegerNo
question_textstringYes
explanationstringNoShown after test submission
difficultystringNoeasy / medium / hard
question_typestringNosingle_choice (default)
source_typestringNoqbank / recall / mock / previous_year
marksfloatNoDefault: 1
negative_marksfloatNoDefault: 0
optionsarrayYesSee format below
Example Request
{
  "subject_id": 2,
  "question_text": "Which valve is most affected in rheumatic fever?",
  "explanation": "Mitral valve is affected due to...",
  "difficulty": "medium",
  "marks": 1,
  "negative_marks": 0.25,
  "options": [
    { "option_key": "A", "option_text": "Aortic",  "is_correct": false },
    { "option_key": "B", "option_text": "Mitral",  "is_correct": true  },
    { "option_key": "C", "option_text": "Tricuspid", "is_correct": false },
    { "option_key": "D", "option_text": "Pulmonary", "is_correct": false }
  ]
}
PUT /questions/admin/:id ADMIN

Update a question's text, metadata, or options. If options array is provided, existing options are deleted and replaced entirely.

PATCH /questions/admin/:id/toggle ADMIN

Toggle is_active on a question. Inactive questions are invisible to students and excluded from dynamic mock test generation. Use this instead of deleting broken or disputed questions.

Response
{ "id": 42, "is_active": false }

Section 5 — Import Pipeline

Bulk import questions from the Python PDF parser

How the Pipeline Works

Admin creates Batch
→
Node notifies Python
→
Python parses PDFs
→
Python POSTs to /receive
→
Admin Previews
→
Admin Approves
→
Questions saved to DB
Set the environment variable PYTHON_SERVICE_URL to auto-trigger Python processing after a batch is created. If not set, pass the batch_id to Python manually.
POST /admin/import-batches ADMIN

Step 1: Create a batch record. If PYTHON_SERVICE_URL is configured, this also notifies the Python service automatically.

FieldTypeDescription
titlestringBatch label (e.g., "Recall 2024")
questions_pdfstringPath or URL to questions PDF
answers_pdfstringPath or URL to answers PDF
Response
{ "batch_id": 7, "message": "Batch created and sent to processing" }
POST /admin/import-batches/:id/receive ADMIN

Step 2 (called by Python, not by admin UI): Python sends the parsed questions here after processing the PDFs. The parsed data is stored and the batch status becomes "completed".

Body sent by Python
{
  "status": "completed",
  "total_questions": 50,
  "failed_questions": 2,
  "questions": [
    {
      "question_text": "Which of the following...",
      "explanation": "The correct answer is B because...",
      "subject_id": 1,
      "topic_id": 3,
      "difficulty": "medium",
      "source_type": "previous_year",
      "source_year": 2023,
      "options": [
        { "option_key": "A", "option_text": "...", "is_correct": false },
        { "option_key": "B", "option_text": "...", "is_correct": true  }
      ]
    }
  ],
  "logs": ["Page 3: ambiguous answer skipped"]
}
GET /admin/import-batches/:id ADMIN

Step 3: Preview the batch. Returns the full parsed question data (from import_logs) so admin can review before approving.

POST /admin/import-batches/:id/approve ADMIN

Step 4: Approve the batch. Reads parsed questions from the batch and saves them permanently to the questions and question_options tables. Questions are tagged with the batch ID for rollback.

Response
{ "message": "Batch approved", "imported": 48, "failed": 2 }
DELETE /admin/import-batches/:id ADMIN

Rollback: Deletes the batch AND all questions that were created from it. Use this if an import had errors or wrong data.

This permanently deletes all questions from this batch. Cannot be undone.

Section 6 — Admin: Mock Test Management

Create fixed and dynamic tests, manage questions

Two test types: fixed — admin manually selects specific questions. dynamic — admin defines generation rules and the system picks random questions per student attempt.
POST /admin/mock-tests ADMIN

Create a new mock test. Set test_type to fixed or dynamic.

FieldTypeRequiredNotes
titlestringYes
descriptionstringNo
test_typestringNofixed (default) or dynamic
duration_minutesintegerNoDefault: 60
total_marksfloatNo
randomize_questionsbooleanNoShuffle order for fixed tests
randomize_optionsbooleanNoShuffle option order
configuration_jsonobjectDynamic onlyGeneration rules (see below)
starts_atdatetimeNoScheduled start time
ends_atdatetimeNoScheduled end time
Dynamic Test Example
{
  "title": "Grand Mock — May 2026",
  "test_type": "dynamic",
  "duration_minutes": 180,
  "configuration_json": {
    "subjects": [
      { "subject_id": 1, "count": 20 },
      { "subject_id": 2, "count": 15 },
      { "subject_id": 3, "count": 15 }
    ],
    "difficulty": { "easy": 30, "medium": 50, "hard": 20 }
  }
}
POST /admin/mock-tests/:id/questions ADMIN

Add questions to a fixed test. Send an array of question IDs with their display order.

Request Body
{
  "questions": [
    { "question_id": 10, "question_order": 1 },
    { "question_id": 25, "question_order": 2 },
    { "question_id": 31, "question_order": 3 }
  ]
}
PATCH /admin/mock-tests/:id/publish ADMIN

Toggle the published status of a test. Only published tests are visible to students. Use this to prepare a test privately before releasing it.

Response
{ "is_published": true }
DELETE /admin/mock-tests/:id/questions/:questionId ADMIN

Remove a specific question from a fixed mock test.

PUT /admin/mock-tests/:id ADMIN

Update test metadata (title, duration, configuration, etc.). Cannot change test_type after creation.

Section 7 — Student: Browsing & Starting Tests

Discover published tests and start an attempt

GET /mock-tests PUBLIC

List all published tests. Use on the exam listing page. Returns basic info (no questions, no configuration details).

Response
[
  {
    "id": 3, "title": "Grand Mock — May 2026",
    "test_type": "dynamic",
    "duration_minutes": 180,
    "total_questions": 50
  }
]
GET /mock-tests/:id PUBLIC

Get the details of a specific published test. Use on the test info/preview page before the student starts.

POST /mock-tests/:id/start USER

Start a test attempt. This is a critical endpoint — it creates the attempt and generates the question snapshot.

  • For fixed tests: loads the admin-curated question list (optionally shuffled)
  • For dynamic tests: randomly selects questions per the configuration rules
  • Saves the exact question set to attempt_questions — it never changes after this point
  • Returns 400 if the student already has an in-progress attempt for this test
Response
{ "attempt_id": 55, "total_questions": 50 }
Save the attempt_id — it's needed for all subsequent attempt endpoints.

Section 8 — Attempts: Answer, Submit & Results

The full lifecycle of a student taking a test

Attempt Lifecycle

POST /start → attempt_id
→
GET /attempts/:id (load questions)
→
POST /answer (for each answer)
→
POST /submit (finalize)
→
GET /result
GET /attempts/:id USER

Load the attempt with all its questions and the student's current answers. While the attempt is in_progress, the is_correct field is stripped from all options. Call this when the student opens or resumes a test.

Response (in_progress)
{
  "id": 55, "status": "in_progress",
  "attempt_questions": [
    {
      "question_order": 1,
      "question": {
        "id": 42, "question_text": "...",
        "QuestionOptions": [
          { "id": 101, "option_key": "A", "option_text": "..." }
          // is_correct is hidden
        ]
      }
    }
  ],
  "answers": [
    { "question_id": 42, "selected_option_id": 101 }
  ]
}
POST /attempts/:id/answer USER

Save or update an answer for a single question. Call this each time the student selects or changes an option. The answer can be changed any number of times before submission. Does not evaluate correctness — that happens on submit.

FieldTypeRequired
question_idintegerYes
selected_option_idintegerYes
Response
{ "message": "Answer saved" }  // or "Answer updated"
POST /attempts/:id/submit USER

Finalize and score the attempt. The backend evaluates every answer, calculates the score, and marks the attempt as completed. Only works if status is in_progress.

  • Checks each selected option against is_correct in the database
  • Applies positive marks for correct, negative marks for wrong answers
  • Unanswered questions get 0 marks
  • Updates all user_answers with is_correct
  • Records time taken
Response
{
  "message": "Test submitted",
  "score": 37.75,
  "total_correct": 40,
  "total_wrong": 7,
  "total_unanswered": 3
}
GET /attempts/:id/result USER

Get the full result of a completed attempt. Returns all questions WITH correct answers, explanations, and what the student selected. Use this for the result/review page.

Response
{
  "score": 37.75, "total_correct": 40,
  "attempt_questions": [
    {
      "question": {
        "question_text": "...",
        "explanation": "The correct answer is B because...",
        "QuestionOptions": [
          { "option_key": "A", "option_text": "...", "is_correct": false },
          { "option_key": "B", "option_text": "...", "is_correct": true  }
        ]
      },
      "user_answer": {
        "selected_option_id": 102,
        "is_correct": false,
        "selected_option": { "option_key": "B", "option_text": "..." }
      }
    }
  ]
}

Section 9 — Bookmarks

Students can save questions for later review

GET /bookmarks USER

List all questions the logged-in student has bookmarked, paginated. Returns the full question with options (no correct answer) for review.

Query Parameters

ParamDefault
page1
limit20 (max 50)
POST /bookmarks USER

Bookmark a question. Safe to call multiple times — returns 200 if already bookmarked.

Request Body
{ "question_id": 42 }
DELETE /bookmarks/:questionId USER

Remove a bookmark. The :questionId is the question's ID, not the bookmark record's ID.

Example
DELETE /api/bookmarks/42

Section 10 — Analytics

Student performance tracking and weak area identification

All analytics endpoints are user-specific — they only return data for the authenticated student. Analytics are computed from completed attempts only.
GET /analytics/summary USER

Overall stats for the student's dashboard card. Total tests taken, accuracy, average score.

Response
{
  "total_attempts": "12",
  "total_correct": "380",
  "total_wrong": "110",
  "total_unanswered": "10",
  "avg_score": "31.5",
  "avg_accuracy": "77.55"
}
GET /analytics/subjects USER

Accuracy breakdown per subject. Use this to show a subject-wise performance bar chart or table. Results are ordered from weakest subject first.

Response
[
  { "subject_name": "Biochemistry", "total_answered": "50", "total_correct": "30", "accuracy_percent": "60.00" },
  { "subject_name": "Anatomy",     "total_answered": "80", "total_correct": "65", "accuracy_percent": "81.25" }
]
GET /analytics/weak-topics USER

Top 10 topics where the student performs worst (minimum 5 questions attempted per topic). Use to power a "Focus on these topics" recommendation widget.

Response
[
  { "topic_name": "Krebs Cycle", "subject_name": "Biochemistry", "total_answered": "12", "accuracy_percent": "41.67" },
  { "topic_name": "ECG Interpretation", "subject_name": "Cardiology", "total_answered": "18", "accuracy_percent": "50.00" }
]
GET /analytics/history USER

Full history of mock test attempts, newest first. Shows score, timing, and result for each attempt. Use for the "My Attempts" history table.

Query Parameters

ParamDefault
page1
limit10
Response
{
  "data": [
    {
      "id": 55, "status": "completed",
      "score": 37.75, "total_correct": 40,
      "time_taken_seconds": 5820,
      "mock_test": { "title": "Grand Mock — May 2026", "total_questions": 50 }
    }
  ],
  "pagination": { "total": 12, "page": 1, "limit": 10, "pages": 2 }
}
